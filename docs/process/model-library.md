# 建物辞書

同じ名前・地域・種類の場所では、成功したGeminiの模型を再利用する。辞書のキーにはMapsの位置やplaceIdを使わない。地域が空の候補は、同名の別の場所と混ざらないよう、辞書へ登録しない。

`modelCache/{key}` はサーバーだけが読み書きする。読むときに辞書の版、場所の一致、模型の形・大きさ、出典を検査し、違っていれば通常の生成へ進む。代替の部品模型や失敗結果は保存しない。辞書を読めない・保存できない場合も、通常の生成と完成した模型の表示は続ける。

生成済みの模型をコピーするときも出典をコピーし、全員に工事中が見えるよう、既存の待ち時間（標準4秒）を使う。本物の生成が失敗した場合は、汎用模型にせず失敗として再試行を受ける。ローカルのstubは開発用のまま。

## ローカルで生成した模型を事前登録する

手元のGemini（agy）が動く環境で、`buildModelTask.prompt`（`functions/src/features/build-model/prompt.ts`）の形式に従って模型JSONを作る。Mapsの名前・説明・位置を入力に使わない。模型ごとに、次の形の要素をJSON配列へ入れる。

```json
[
  {
    "provider": "agy",
    "identity": { "name": "白骨温泉", "area": "長野県松本市", "category": "onsen" },
    "model": {
      "source": "argon",
      "json": { "version": 1, "parts": [] }
    }
  }
]
```

`parts` は説明のため空にしている。実際には生成した部品を入れる。参考資料を使った場合は、`model.reference` に `text`・`url`・`license` を入れ、出典を残す。

```sh
npm run build --prefix functions
# 検証だけ。本番にもファイルにも書かない
node scripts/model-library.mjs /path/to/models.json
# 検証を通った一覧を、配布用データへ登録する
node scripts/model-library.mjs /path/to/models.json functions/src/features/build-model/logic/prebuilt.ts
npm run build
```

部品の数・色・位置・模型の版、不正な出典、同じ場所の重複を検査する。登録用の一覧は5,000件まで受け付ける。登録したファイルはPRで見た目もレビューし、ユーザーの確認後に本番へ反映する。配布用一覧には、見本の場所の一覧（`suggest-places/logic/catalogue.ts`）の151か所を、2026-11-18に手元のagy（gemini-4-argon-medium）で作って入れた（かめの決定、`todo/humans/2026-11-16-origin-model-release.md`）。外観はKnowledge GraphなどのAPIを使わず、agyのウェブ検索で調べさせた（Googleマップの情報は使わない、と指示した）。そのため `model.reference` は付けていない。一覧にない場所は、実際の生成成功時にFirestoreの辞書へ蓄積する。

### 都道府県別に増築する（#431）

47都道府県で各100件を目安に進める。既存模型を検証して件数に含める。生成結果は Git 管理外の `.harness/model-library-expansion/` に1件ずつ保存する。別の端末で再開する場合は、このディレクトリにある候補と検証済み模型を引き継ぐ。

```sh
agy models
npm run build --prefix functions
node scripts/model-library-batch.mjs status
node scripts/model-library-batch.mjs candidates --prefecture 長野県 --limit 1 --execute
```

`agy models` で `gemini-4-argon-medium` を確認してから進める。候補は Flash が作る。端末に出る保存先を開き、候補の実在、名前、市町村、種類、既存候補との重複を確かめたあと、1件試す。

```sh
node scripts/model-library-batch.mjs generate --prefecture 長野県 --limit 1 --execute
node scripts/model-library-batch.mjs export
```

`--execute` を省くと生成せずに件数を表示する。失敗時はそこで止まり、同じコマンドを再度実行すると保存済みの模型を飛ばして再開する。強制終了で `batch.lock` が残った場合は、実行中のバッチがないと確認してからそのファイルを取り除く。通常の agy の日次上限（既定は Flash 30回、Argon 20回）を使うため、生成は分けて実行する。一括生成のときだけ `AGY_MAX_ARGON_CALLS` と `AGY_MAX_CALLS` を環境変数で上げてよい（かめの決定、`todo/humans/2026-11-21-model-library-argon-batch-limit.md`）。配布用辞書へ登録済みの模型は、作業フォルダに残っていても追加分に数えない。

#### 候補と向きの指示

候補（Flash）は、旅行者がよく訪れる定番から順に、旅行者や検索で最もよく使われる正式な表記で選ばせる。種類は shrine・nature・town・food を早めに入れて散らし、その県で定番と言えない種類（東京の温泉、沖縄のスキーなど）は選ばせない。同じ種類は1県3件まで。一覧外の種類などで弾いた候補は、その1件だけを除いて理由を表示する（`candidatePrompt`）。

模型（Argon）には `VIEW_RULE` を足す。アプリのカメラ(40,33,40)からは+z側と+x側の面だけが見えるので、部品は台座のx・zの軸に沿わせたまま（yの回転は0・90・180・270）、見せ場を+z側か+x側に向け、手前を低く奥を高く並べる。手本は熱海温泉の模型。カメラに合わせて45度回させる指示は、台座の向きから外れるので使わない（2026-11-21 に長野県で比べた）。

#### agy の利用枠（2026-11-21 に確認）

agy の枠は、Gemini のモデル全体の枠（5時間ごとと週ごと）と、Argon だけの週の枠の2段になっている。残りは `agy -p "/usage"` で見られる。Argon の週の枠を使い切ると `Individual quota reached ... Resets in 100h` のように止まり、Flash は使える。枠の回数は公表されていない。2026-11-21 は Argon が66回成功したところで止まり、リセットは 2026-11-25 17:42（日本時間）だった。一括生成を回す前に `/usage` で Argon の残りを確かめる。

Argon の週の枠を使い切ったときは、`AGY_ARGON_MODEL=gemini-4-hydrogen-medium` と明示したときだけ、Hydrogen で模型を作ってよい（Lazyturtle0852 の決定、`todo/humans/2026-11-22-hydrogen-model-generation.md`。agy は手元で動かすので料金はかからない）。明示しなければ Argon だけを使う。

`generate` に `--per-call 3` のように付けると、1 回の呼び出しで最大 5 件の模型をまとめて頼む。agy は呼び出しごとの前置きの入力で枠が減るので、まとめると 1 件あたりの枠と時間が減る。返った配列は 1 件ずつ検査し、崩れた件だけを `failures.jsonl` に残して、ほかは保存する。既定は 1 件ずつ。

- Wikipedia で合わなかった 279 件と、当たった記事が場所そのものでなかった 144 件（例：西島園芸団地 → 記事「団地」）は、エージェントに名前と市町村で Web 検索させ、場所そのものを説明するページ（公式サイト、自治体・観光協会、Wikipedia の個別記事）で確かめた。正式な名前が違った 14 件は名前を直して登録した（例：果実の森 原田農園 → 果実の里 原田農園、ことひら温泉郷 → こんぴら温泉郷）。正式名が元の名前を含むだけのもの（例：平川動物公園 → 鹿児島市平川動物公園）は、通り名のまま残した。

## 出発地点

`resolveOrigin` は既知の駅・街を手元の表で引き、未知の名前を既存のPlacesテキスト検索で調べる。表の「東京」が住所の一部に含まれるという理由で、その住所を東京駅へ置き換えない。検索できない場合は、名前の入力を促し、旅の作成や変更を保存しない。

`changeOrigin` は検索の前と保存のトランザクション内でメンバーか確かめる。入力画面を開いたときの名前を `expectedOrigin` として渡し、ほかの人が変更した場合は上書きしない。位置の変更と全ルートの時刻・距離の再計算を同じトランザクションで保存する。訪問先の順序は変えない。クライアントからの位置の更新は拒否する。

未知の地点の検索には既存のPlacesテキスト検索の上限を使う。検索は入力中には行わず、旅を作る・変更を保存する操作につき最大1回。費用を伴う本番の呼び出し可否はデプロイ前にユーザーへ確認する。ローカルEmulatorではPlacesを呼ばない。
