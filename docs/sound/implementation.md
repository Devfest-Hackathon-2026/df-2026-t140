# 効果音の再生

2026-11-09、柔らかいポップ・バブル系へ候補を再選定したあと、たかなの[試聴後の採用指定](selections.md)を反映した。候補A/B/Cの名前は固定し、catalogのselectedで採用IDを記録する。selected=nullは無音。候補は `sound/` に保管し、配信する17音源だけを `web/public/sounds/` にコピーする。音声データは加工せず、再生時のゲインで音量を調整する。保存成功のぴろりんは同じ原音・音量を維持する。配信ファイルの一覧と出典は [sounds/README.md](../../web/public/sounds/README.md) にある。

## 共通ヘルパー

入口は `web/src/shared/lib/sound.ts`。汎用の再生処理は `soundPlayer.ts` にあり、1つのAudioContext、音源の取得・デコード結果のキャッシュ、音量、停止、重複抑制をまとめて扱う。音声の非対応・取得失敗は利用者の操作へ例外を返さない。

```ts
import { playSound, prepareSounds, setSoundSettings } from '@/shared/lib'

// 人の操作の中で呼ぶ。アプリ全体でもpointerdown/keydownで準備する。
prepareSounds()
const stop = playSound('select')

// 途中で不要になった音は、読み込み中でも取り消せる。
stop()

// 非同期の通知。再描画などで同じイベントが来ても鳴らさない。
playSound('build-complete', { channel: 'notification', key: '固有のイベントID' })
setSoundSettings({ muted: true })
```

| API | 用途 |
| --- | --- |
| `prepareSounds()` | 初回操作でAudioContextを準備し、採用音を先読みする。起動時に音は出さない |
| `playSound(name, options?)` | 音を再生し、読み込み中・予約中も有効な停止関数を返す |
| `stopSounds()` | 読み込み中の再生要求と再生中・予約中の音を取り消す |
| `setSoundSettings({ volume, muted })` | 0〜1の音量とミュートを設定し、この端末に保存する |
| `useSoundSettings()` | 設定を画面へ反映する。ホームの設定欄で使用 |
| `focusTourSounds(true / false)` | 旅の再生中は共同作業の通知音を抑える |

初期音量は35%。ホームから音量・ミュートを変更できる。設定保存には既存のstorageヘルパーを使い、複数人シミュレーションでも端末ごとの設定を分離する。

同時再生は3音まで。同じ音の短い連打を抑え、通知音は350ms以内の同種イベントをまとめる。イベントIDの重複記録は直近256件。音源の取得や準備に1秒を超えた再生要求は、あとから鳴らさず破棄する。画面を隠したときとミュート時は、ループや予約した音も止める。元からあるシャッター用APIも同じプレイヤーを使う。

| 無音の21行 | T02、T03、T04、T09、T10、T11、W03、W10、W11、W12、B02、B03、B04、B10、B11、M01、M04、M10、M15、S05、S06 |

仲間の通知は半分の音量にする。完成・完成通知・しおりへの追加では同じ音を重ねない。建築イベントは30秒以上前のものを音で知らせない。旅の再生はuseShioriTourの段階切替で音を鳴らし、出発音のあとに走行音を小さくループする。途中で止める・ページを離れると、その段階の予約音とループを止める。動きを減らす設定で走行を省くときは車の音も鳴らさない。

購読はFirestoreのキャッシュ・サーバーの同期状態を通知判定まで渡す。一覧は削除確認中にもキャッシュへ切り替わるため、旅の文書の同期状態で通信断を区別する。初回・キャッシュ・再接続で届いたデータは無音で、次の変化を見分ける基準にする。切断中に終わった検索や退出を、再接続時に新着として鳴らさない。検索結果への自動移動音も通知として扱い、旅の再生中は抑える。

## 確認

`node --test scripts/sound.test.mjs` で、購読の初回・再接続、初回準備、キャッシュ、キャンセル、重複、優先度、ミュート、非表示、取得失敗と、採用IDの原音とのバイト一致を確認する。既存の `scripts/web.test.mjs` からも読み込むため、CIの確認に含まれる。ブラウザでは実際の操作から音源を取得し、Web Audioの再生開始まで確認する。スピーカーからの聞こえ方やスマホ実機での音量は、実機で別途確認する。
